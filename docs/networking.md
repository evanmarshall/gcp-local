# Compute Engine networking and Connectivity Tests (local emulation)

Status: networks, subnetworks, firewall rules, routes, routers, peerings, VM
instances (as topology endpoints), and Network Management Connectivity Tests
are implemented locally in one in-memory provider
(`internal/providers/compute`). Two real-GCP recordings back it, and the local
provider matches both in comparison mode: `vpc-firewall-connectivity`
(2026-10-11) covers the VPC control plane and Connectivity Tests for
IP-address endpoints, and `vm-connectivity-nat-peering` (2026-10-12) covers
Connectivity Tests between VM instances, peering, and Cloud NAT. Behavior
outside those recordings is a local model, not a fidelity claim.

## Surface

- Compute v1 REST routes generated by `tools/genapi`: networks
  (create/get/list/delete, addPeering, removePeering), subnetworks
  (create/get/list/delete, get/setIamPolicy), firewalls (create/get/list/
  update/delete), routes, routers with Cloud NAT entries, zonal instances
  (insert/get/list/delete), and `globalOperations.get/list`,
  `regionOperations.get`, and `zoneOperations.get`.
- Network Management v1 Connectivity Tests:
  `POST /v1/projects/{p}/locations/global/connectivityTests?testId=ID`, `GET`
  and `DELETE .../connectivityTests/ID`, list (`resources`), and
  `POST .../connectivityTests/ID:rerun`. There is no `:run` method; the real
  API has none.
- Regions are placement attributes, not namespaces (the storage precedent):
  every compute resource lives in the project's global scope so network
  references resolve across regions. Projects are isolated from each other.
- Permission plans follow the documented rows (`compute.*` and
  `networkmanagement.connectivitytests.*`), backed by pinned
  `roles/compute.admin`, `roles/compute.networkAdmin`, `roles/compute.viewer`,
  `roles/networkmanagement.admin`, and `roles/networkmanagement.viewer`.
  `instances.insert` checks `compute.instances.create` plus the documented
  `compute.disks.create` and `compute.subnetworks.use`; get/list/delete and
  `zoneOperations.get` check their own `compute.*` permission.
  Compute denials use the compute error body; Network Management denials use
  the standard `PERMISSION_DENIED` envelope.

## Recorded scenario: `vpc-firewall-connectivity`

Produced by `gcp_validation/networking.py` against a sandbox project with no VM
instances. `sh scripts/check_rest_recordings.sh` replays it locally. What it
establishes, and what the provider now does:

- Self-links use `https://www.googleapis.com/compute/v1/...`, and a
  subnetwork's `region` is the region's link.
- Documents carry exactly the recorded field sets. A network has `id`, `name`,
  `kind`, `selfLink`, `selfLinkWithId`, `creationTimestamp`,
  `autoCreateSubnetworks`, `routingConfig` (`routingMode`, plus
  `bgpBestPathSelectionMode: LEGACY`), `networkFirewallPolicyEnforcementOrder`
  (`AFTER_CLASSIC_FIREWALL`), and `description` when one was given; `mtu`,
  `subnetworks`, and `peerings` appear only when set or non-empty. A
  subnetwork adds `allowSubnetCidrRoutesOverlap`, `fingerprint`,
  `privateIpv6GoogleAccess`, `purpose` (`PRIVATE`), and `stackType`
  (`IPV4_ONLY`), with no empty `description` or `secondaryIpRanges`. A
  firewall always has `description` and omits empty `denied`, `targetTags`,
  and ranges.
- Some validation fails asynchronously. An insert of a subnetwork whose range
  overlaps another subnetwork of the network returns 200 and an operation that
  finishes `DONE` with error `INVALID_USAGE`; nothing is created. Deleting a
  network that subnetworks (locally also firewalls, routes, routers, or
  instances) still
  use returns 200 and an operation `DONE` with
  `RESOURCE_IN_USE_BY_ANOTHER_RESOURCE`; the network is kept. Both operations
  are readable through `regionOperations.get` / `globalOperations.get`.
  Deleting an absent subnetwork, firewall, route, or router returns 404.
- `addPeering` accepts the current body
  `{"networkPeering": {"name", "network", "exchangeSubnetRoutes"}}` with a
  full URL or relative network name, and the legacy top-level
  `{"name", "peerNetwork"}`. The recorded peering fields are rendered
  (`autoCreateRoutes`, `connectionStatus`, `exchangeSubnetRoutes`,
  `export/importCustomRoutes`, `export/importSubnetRoutesWithPublicIp`,
  `name`, `network`, `stackType`, `state`, `stateDetails`, `updateStrategy`).
  The recording read the peering after both directions were added and saw
  `ACTIVE`; locally a peering is `INACTIVE` until the peer network has a
  peering back, matching GCP's documented behavior but not recorded.
  `removePeering {"name"}` removes one side; an unknown name returns 400.
- Connectivity Tests create returns a finished long-running operation
  (`projects/P/locations/global/operations/...`, `done: true`, the test in
  `response`). A test reads back with exactly `createTime`, `destination`,
  `name`, `protocol`, `reachabilityDetails` (`result`, `traces`,
  `verifyTime`), `source`, and `updateTime`; `description` appears when given.
  Delete returns an operation and later reads 404. The result is stored when
  the test is created or rerun; reads do not re-evaluate the topology.

## Recorded scenario: `vm-connectivity-nat-peering`

Produced by `gcp_validation/vm_connectivity.py` (`VmFixture`, built on the
networking fixture): networks a (`10.10.0.0/24`) and b (`10.20.0.0/24`) in
`us-central1`, each with an INGRESS rule allowing `tcp:8080` from
`10.10.0.0/24`; e2-micro instances vm1 and vm2 in a and vm3 in b, with no
access config and no service account. Tests use
`{"instance": "projects/P/zones/us-central1-a/instances/NAME"}` endpoints and
TCP. The recording establishes, and the provider reproduces:

- `instances.insert` (boot disk from the debian-12 family, one interface on a
  subnetwork) and a router insert with
  `nats: [{name, natIpAllocateOption: AUTO_ONLY,
  sourceSubnetworkIpRangesToNat: ALL_SUBNETWORKS_ALL_IP_RANGES}]` each return
  a `compute#operation` that is `DONE`.
- Every trace's first firewall step is the implied `default-allow-egress`.
- vm1 to vm2:8080 is `REACHABLE`: `START_FROM_INSTANCE`,
  `APPLY_EGRESS_FIREWALL_RULE`, `APPLY_ROUTE`, `ARRIVE_AT_INSTANCE`,
  `APPLY_INGRESS_FIREWALL_RULE`, `DELIVER`.
- vm1 to vm2:9090 is `UNREACHABLE` with the same steps ending in `DROP` cause
  `FIREWALL_RULE` (no rule allows the port).
- vm1 to vm3:8080 before peering is `UNREACHABLE`: `START_FROM_INSTANCE`,
  `APPLY_EGRESS_FIREWALL_RULE`, `APPLY_ROUTE`, `DROP` cause
  `PRIVATE_TRAFFIC_TO_INTERNET`. After peering both directions it is
  `REACHABLE` with the full instance-to-instance steps. Note the contrast with
  the IP-only recording, where an address in the peered network still dropped
  right after peering: the provider applies peering routes only to instance
  endpoints.
- vm1 to `8.8.8.8:443` without Cloud NAT is `UNREACHABLE`:
  `START_FROM_INSTANCE`, `APPLY_EGRESS_FIREWALL_RULE`, `APPLY_ROUTE`, `DROP`
  cause `PRIVATE_GOOGLE_ACCESS_DISALLOWED`. With a NAT covering all
  subnetworks of network a in `us-central1` it is `REACHABLE`:
  `START_FROM_INSTANCE`, `APPLY_EGRESS_FIREWALL_RULE`, `APPLY_ROUTE`,
  `DELIVER`.
- Instance and subnetwork documents, step details beyond state, firewall
  display name, and drop cause, and instance addresses were not recorded.
  Locally an instance gets the lowest free host address of its subnetwork
  (skipping the network, gateway, and last two addresses), or a requested
  free `networkIP`.

## Analyzer semantics

The analyzer serves both Connectivity Tests and the local
`POST /_local/networking/reachability` surface (verdicts `unknown`, `dropped`,
`unsupported`). It follows the recorded step order for IP-address endpoints:

1. `START_FROM_PRIVATE_NETWORK` from the subnetwork that contains the source
   address (within the source network when the test names one).
2. `APPLY_EGRESS_FIREWALL_RULE`: the highest-priority enabled EGRESS rule of
   the source network that matches the destination, protocol, and port (deny
   wins at equal priority), or the implied `default-allow-egress` rule.
3. `APPLY_ROUTE`, then a final state.

Recorded outcomes (no VM instances exist in the recording):

- A destination inside a subnetwork of the source network is `UNDETERMINED`
  with `ABORT` cause `UNKNOWN_IP`, whatever the ingress rules say, because no
  endpoint owns the address. The recording shows this for both an allowed and
  a blocked port.
- A private destination outside the source network's subnetworks follows the
  default route and is `UNREACHABLE` with `DROP` cause
  `PRIVATE_TRAFFIC_TO_INTERNET`. GCP returned this for an address in another
  network both without peering and immediately after peering both directions.
  The provider reproduces that observation and does not apply peering routes;
  the recording does not show whether GCP's answer changes later.

Local model, not recorded: an egress deny rule ends with `DROP` cause
`FIREWALL_RULE` (`UNREACHABLE`).

For IP-address endpoints the analyzer never reports `REACHABLE`. An address
that belongs to a modeled instance is a gap (name the instance instead).

Instance endpoints (the source must be an instance; the destination is an
instance or an IP address) follow the VM recording:

1. `START_FROM_INSTANCE`, then `APPLY_EGRESS_FIREWALL_RULE` as above (an
   egress deny drops with `FIREWALL_RULE`, a local model).
2. Same network, or a network peered in both directions with
   `exchangeSubnetRoutes`: `APPLY_ROUTE` (subnet or peering-subnet route),
   `ARRIVE_AT_INSTANCE`, `APPLY_INGRESS_FIREWALL_RULE` with the destination
   network's highest-priority matching untagged INGRESS rule (source and
   destination ranges, protocol, port; deny wins at equal priority). An allow
   rule ends in `DELIVER` (`REACHABLE`); no matching rule (the implied
   `default-deny-ingress`) or a deny rule ends in `DROP` `FIREWALL_RULE`.
3. Another network with no peering: the default route, then `DROP`
   `PRIVATE_TRAFFIC_TO_INTERNET`.
4. The recorded internet destination `8.8.8.8`: the default route, then
   `DELIVER` when a Cloud NAT on a router of the instance's network and region
   uses `ALL_SUBNETWORKS_ALL_IP_RANGES`, or `DROP`
   `PRIVATE_GOOGLE_ACCESS_DISALLOWED` when no NAT exists there.

These flows are coverage gaps instead of verdicts. Connectivity Tests
create/rerun returns 501 and the local surface returns `unsupported`:

- a source address outside every modeled subnetwork of the source network;
- a destination matched by an untagged static route (next hops are not
  modeled);
- public destinations from IP-address sources; from instances, any internet
  destination other than the recorded `8.8.8.8`, a source subnetwork with
  Private Google Access, or NAT gateways using other source selectors
  (`LIST_OF_SUBNETWORKS`, primary ranges only);
- an IP-address source with an instance destination, a missing instance, or
  an IP-address destination owned by an instance;
- one-sided peering, peering without subnet route exchange, and subnetwork
  ranges that overlap across networks;
- firewall rules with source or target tags that could decide an instance
  flow (instance tags and service accounts are not modeled);
- cross-project endpoints and cross-project peering.

## Explicit gaps

- Instances are topology endpoints only: one network interface, no access
  configs (external IPs), IPv6, alias ranges, network tags, or service
  accounts; a second interface or any address config returns 501. Nothing
  runs, boot disks are not separate disk resources, and instance
  start/stop/update methods are not routed. Deleting a subnetwork or network
  an instance uses finishes `DONE` with `RESOURCE_IN_USE_BY_ANOTHER_RESOURCE`
  (a local model; only a network still used by a subnetwork is recorded).
- Routers accept the Compute v1 NAT shape (`sourceSubnetworkIpRangesToNat`,
  `subnetworks[].name`); manually allocated NAT addresses return 501.
- Internal load balancers, custom-route next hops, PSA/PSC, Cloud SQL, and
  hierarchical or network firewall policies are not analyzed.
- Network Management `operations.get` is not routed; create, rerun, and delete
  return already-finished operations.
- The auto-created default route is implied by the analyzer and not listed by
  `routes.list`.
- No persistence across restarts.
