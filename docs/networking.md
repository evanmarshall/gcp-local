# Compute Engine networking (local emulation)

Status: the first control-plane slice is implemented locally - networks,
subnetworks, firewall rules, and routes with compute-style long-running
operations. No cloud recording covers these resources yet, so nothing here is
a cloud-fidelity claim (issue #16 tracks the recording work).

## Surface

- REST v1 routes generated by `tools/genapi` from the pinned slice:
  networks, subnetworks, firewalls, and routes with create/get/list/delete,
  firewall update via PUT, plus global and regional operation reads.
- Regions are placement attributes, not namespaces (the storage precedent):
  every compute resource lives in the project's global scope so network
  references resolve across regions.
- Deletes report DONE operations. Deleting a network that subnetworks still
  reference fails at the boundary (400 failedPrecondition). Firewalls and
  routes that name a missing network are refused before any state change.
- Gateway address of a subnetwork derives from its CIDR's first host address.
- Permission plans follow the documented compute rows, backed by pinned
  `roles/compute.admin`, `roles/compute.networkAdmin`, and `roles/compute.viewer`
  snapshots.

## Explicit gaps

Routers, Cloud NAT, peering, PSA/PSC, and Cloud SQL configuration are not
implemented and are never reported as reachable; the reachability analyzer
(#17) must list them as unknown rather than approximating them.
