# Memorystore for Redis

The Memorystore provider serves a slice of the Redis v1 REST control plane at `/v1/projects/{project}/locations/{region}/...` (select it with `-services=...,redis`). Each instance is backed by its own real **Redis 7.2.16** server, built from the official source release pinned in [toolchains/redis.json](../toolchains/redis.json). The provider authenticates and authorizes every call with the shared IAM engine before any backend start, probe, or change.

**Status:** the control plane is cloud-recorded (`memorystore-redis-instance-admin`, below). The IAM engine uses `roles/redis.admin`, `roles/redis.editor`, and `roles/redis.viewer` recorded from Google Cloud.

## Surface

Routes are generated by `tools/genapi` from Google's Redis v1 discovery document (revision 20260812), pinned with its SHA-256 in [api/discovery/redis-v1.manifest.json](../api/discovery/redis-v1.manifest.json). Generation selects an explicit method allowlist; the rest of the document (clusters, backups, ACL policies, import/export, failover, upgrade, maintenance) is not routed.

| Method | Permission | Behavior |
| --- | --- | --- |
| `instances.create` | `redis.instances.create` | Starts the instance's server, then returns a completed operation |
| `instances.get` / `instances.list` | `redis.instances.get` / `redis.instances.list` | Instance metadata; list pages with `pageSize`/`pageToken` |
| `instances.patch` | `redis.instances.update` | `updateMask` of `displayName`, `labels`, `memorySizeGb` (camel or snake case) |
| `instances.delete` | `redis.instances.delete` | Stops the server and discards its keyspace |
| `instances.getAuthString` | `redis.instances.getAuthString` | `{"authString": ...}`, or `{}` when AUTH is disabled (as the API reference states) |
| `operations.get` / `operations.list` | `redis.operations.get` / `redis.operations.list` | The scope's completed operations (newest 1,000 kept) |

Permissions follow the [Memorystore access-control](https://docs.cloud.google.com/memorystore/docs/redis/access-control) page. Memorystore has no instance-level IAM policies, so every check targets the project. Of the predefined roles, only Redis Admin includes `redis.instances.getAuthString`.

Mutations return `google.longrunning.Operation` with `metadata.@type` `type.googleapis.com/google.cloud.redis.v1.OperationMetadata` (`createTime`, `endTime`, `target`, `verb`, `apiVersion`) and the `Instance` (or `google.protobuf.Empty` for delete) as `response`. The local server is ready before the response is written, so operations are already `done: true`; GCP takes minutes, and its intermediate `CREATING`/`UPDATING`/`DELETING` states are not modeled.

Instances report `tier` `BASIC`, `redisVersion` `REDIS_7_2`, `state` `READY`, `transitEncryptionMode` `DISABLED`, `connectMode` `DIRECT_PEERING`, `locationId`/`currentLocationId` (default `{region}-a`), `authorizedNetwork` (default `projects/{project}/global/networks/default`), `createTime`, `memorySizeGb`, `authEnabled`, labels, display name, and `host`/`port`.

Explicitly refused with 501 `UNIMPLEMENTED` (never silently accepted): `STANDARD_HA`, other Redis versions, `SERVER_AUTHENTICATION` transit encryption, `PRIVATE_SERVICE_ACCESS`, non-empty `redisConfigs`, replicas, read replicas, persistence, maintenance policy, CMEK, reserved/secondary IP ranges, tags, update masks for those fields, `operations.list` filters, and the `-` all-locations wildcard. Empty values of those fields are accepted, as Terraform sends them. Unknown fields, a missing `updateMask`, invalid IDs, non-zone `locationId`, out-of-range `memorySizeGb` (1–300 for Basic Tier), and non-region locations return 400. A duplicate ID returns 409; a missing instance or operation returns 404. Denials return 403 `Permission '<permission>' denied on resource '//redis.googleapis.com/...' (or it may not exist).`. Error message text has not been compared with GCP.

## Ownership and lifecycle

| Data | Owner |
| --- | --- |
| Keyspace (all Redis data) | That instance's `redis-server` process, in memory only |
| Instance metadata, AUTH strings, operations | Provider catalog, scoped by project + region |
| Instance references (`//redis.googleapis.com/projects/.../instances/...`) | Shared index, published after the server is ready; removed after it is stopped |
| Server processes, ports, private directories | Backend fleet for the project + region scope (backend manager key `redis`) |

The backend manager owns one fleet per project and region. It starts the fleet lazily inside `Manager.Use`, after authorization, by creating a private (`0700`) temporary directory. `instances.create` launches one server per instance inside that call: it reserves a random loopback port, writes an owner-only (`0600`) `redis.conf` containing the ACL users, and starts `redis-server <config>` with only `PATH`, `HOME`, and `TMPDIR` in its environment. No credentials, ADC, or proxies reach the child. The call returns after an authenticated `PING` succeeds. If publishing the metadata fails, the new server is stopped, so a rejected create leaves no backend running. Every later call in the scope probes every server. An exited server marks the scope failed (503 `UNAVAILABLE`) until it is reset.

Delete stops that server and removes its directory before the metadata is dropped. Reset stops every server in the selected project + region, removes the directory, and then clears that scope's catalog and index entries; other regions and projects keep running. Shutdown stops all servers. Nothing persists across restarts: servers run with `save ""` and `appendonly no`, matching Basic Tier's default of no persistence.

`memorySizeGb` sets `maxmemory` (with Memorystore's default `maxmemory-policy volatile-lru`); a patch applies the new limit with `CONFIG SET` over the provider's admin connection and keeps the data, as the Memorystore scaling documentation describes. The brief connection reset GCP documents during scaling is not modeled.

## Endpoint and AUTH semantics

Connect a Redis client to the `host` and `port` the API reports. `host` is always `127.0.0.1`; `port` is not `6379` (in GCP, `host` is a private VPC address and `port` is `6379`).

```sh
redis-cli -h 127.0.0.1 -p 4568 -a "$AUTH_STRING" PING   # port from instances.get, string from getAuthString
```

- **Packaged environment:** each instance gets a port from the environment's data-plane range (`GCP_LOCAL_DATA_PORTS` in `gcp-local env`, 4568-4583 by default), published on host loopback. The lowest free port is used and released on delete. A full range returns 429 `RESOURCE_EXHAUSTED`; widen it with `up --data-ports FIRST-LAST` on a new directory (at most 64 ports).
- **Delete and reset** close the port and every open session on it.
- **Without `-data-ports`** (a bare `gcp-local` run), `port` is the server's own random loopback port.
- Idle connections through the packaged entry point close after one hour.

Memorystore does not evaluate IAM per Redis connection. A connection is governed by network reachability (the client must be on the authorized VPC) plus, when `authEnabled` is true, the instance's AUTH string. gcp-local enforces the AUTH part and nothing else:

- `authEnabled: true`: the client-facing `default` user requires the generated UUID-format AUTH string. Unauthenticated commands get `NOAUTH`, and a wrong string gets `WRONGPASS`. No unauthenticated path to that server exists.
- `authEnabled: false`: the `default` user has no password, as in Memorystore.
- Network reachability is **not** modeled. Anything that can reach the host's loopback can reach the port; `authorizedNetwork` is recorded but never checked against Compute networks, and the Connectivity Tests analyzer does not consider Redis endpoints. Holding `redis.instances.getAuthString` is the IAM control that gates who can learn the AUTH string; it does not gate connections.
- The commands Memorystore [documents as blocked](https://docs.cloud.google.com/memorystore/docs/redis/supported-commands) (`ACL`, `BGREWRITEAOF`, `BGSAVE`, `CLIENT`, `CLUSTER`, `COMMAND`, `CONFIG`, `DEBUG`, `LASTSAVE`, `MIGRATE`, `OBJECT`, `REPLICAOF`, `SAVE`, `SHUTDOWN`, plus the `SLAVEOF` alias) are removed from the `default` user with ACL rules, so they return `NOPERM`, the error class the documentation states. Some client libraries issue `CLIENT SETINFO` or `COMMAND` on connect; they see the same refusal they would in production.
- The provider uses a separate ACL user (`gcp-local-admin`) with a random per-server password for readiness probes and `CONFIG SET`. Its password is generated in process and written only to the owner-only config file. Unlike Memorystore, that extra ACL user exists on the server.

In-transit encryption (TLS) is not supported; the source build is compiled with `BUILD_TLS=no`.

## Installation and platforms

```sh
python3 scripts/install_redis.py        # Linux amd64/arm64; needs a C compiler and make
bin/gcp-local -services redis -identity-config ... -iam-config ... \
  -redis-server "$PWD/.tools/redis/bin/redis-server"
```

The installer downloads `redis-7.2.16.tar.gz` from download.redis.io over HTTPS, ignoring ambient proxies. It verifies the tarball's size and the SHA-256 published in the [redis-hashes](https://github.com/redis/redis-hashes) list. Extraction accepts only regular files and directories under the release folder. It then builds with the bundled dependencies (`make BUILD_TLS=no USE_SYSTEMD=no`) and installs `redis-server` and `redis-cli` into `.tools/redis/bin`. A compiled binary is not byte-reproducible across compilers, so the pin is the source checksum plus the version the server reports. The installer records both in `.tools/redis/build.json`, and the provider refuses a `redis-server` that does not report `v=7.2.16`. Redis 7.2 is BSD-3-Clause licensed; no binaries are vendored.

Verified on the arm64 moo guest (Debian 12, GCC 12): about 30 s to build, and the server links only glibc and libm. linux/amd64 is listed in the pin but has not been built in this slice. macOS is not a supported installer target.

## Verification

```sh
sh scripts/go.sh test -race ./internal/providers/memorystore   # fake driver and authorizer
sh scripts/check_redis.sh                                       # real redis-server, loopback-only runner
```

Unit tests cover authorization before any backend start (denied, viewer, and anonymous callers start nothing), the create/get/list/patch/delete/getAuthString/operations lifecycle and wire shapes, validation and explicit gaps, project and region isolation, reset clearing only its scope, compensation when publication or launch fails, pagination, and the production dependency on recorded roles. `TestProductionPlansNeedRecordedRoles` requires registration with the real IAM engine and the recorded roles to succeed.

`check_redis.sh` runs `TestRealRedisLifecycle` and `TestRealRedisPublishedPort` against the real server with network access limited to loopback. A denied create starts no backend. On the AUTH-enabled instance, `NOAUTH` and `WRONGPASS` are enforced, and `SET`/`GET` succeed after `AUTH` with the string from `getAuthString`. `CONFIG`, `SHUTDOWN`, `ACL`, `CLIENT`, and `BGSAVE` return `NOPERM`. An AUTH-disabled instance answers without credentials. A memory patch changes the server's `maxmemory` and keeps the data. Delete closes the port. Reset closes the selected scope's ports while another project's server keeps answering. Through a published range, the API reports the range's first port, AUTH is enforced the same way, a full range returns 429 without creating the instance, delete ends an open session and closes the port, and reset closes the rest.

The `memorystore-redis-instance-admin` scenario ([gcp_validation/memorystore.py](../gcp_validation/memorystore.py)) is written for a later authorized recording. It creates one labeled Basic Tier 1 GB `REDIS_7_2` instance in `us-central1` with AUTH enabled, and enforces limits of one instance, 1 GB, and 2,400 s. The run writes an owner-only manifest before creating the instance, and cleanup deletes only that labeled instance and waits for a 404. The scenario records shapes only: never the AUTH string, private host, or port. The recording is described below.

## Recorded scenario

`memorystore-redis-instance-admin` was recorded and revalidated against real GCP on 2026-10-12 with
one Basic Tier 1 GB REDIS_7_2 instance in us-central1-a, on a run-owned VPC, deleted with the network
at the end of each run. The local provider matches it in comparison mode
(`sh scripts/check_rest_recordings.sh`). It covers create/get/list/patch/delete operations and their
`google.cloud.redis.v1` metadata, the instance field set, the AUTH string shape (never its value),
denied read/getAuthString/delete (403), a duplicate (409), a patch without an update mask (400), and
404 after delete. The first revalidation diverged because GCP chooses the zone when none is given;
the recorder now pins `locationId`. Values of service-managed fields the local model fills
(`maintenanceVersion`, `nodes`, `persistenceConfig`, `persistenceIamIdentity`, `readReplicasMode`,
`reservedIpRange`) are stand-ins; only their presence is recorded.

In the packaged environment, host clients reach each instance on its reported port
([Endpoint and AUTH semantics](#endpoint-and-auth-semantics)). `scripts/smoke_environment.py`
creates an AUTH-enabled instance, checks `NOAUTH` and `WRONGPASS` from the host, runs `SET`/`GET`
after `AUTH`, and requires delete to end the session and close the port; it repeats this without AUTH
in a second environment and in a standalone `docker run`.
