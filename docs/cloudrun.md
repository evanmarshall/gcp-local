# Cloud Run v2 (local emulation)

Status: services, revisions, and operations are implemented locally; container
execution rides the Docker Engine API; invocation enforces the invoker contract.
Cloud-recorded conformance for Cloud Run is not yet recorded, so no behavior
here is a cloud-fidelity claim yet (#13 tracks that work).

## Surface

- REST v2 routes on the shared listener: services create/get/list/update/delete,
  revisions list/get/delete, operations get/list, and service IAM policy
  get/set. Route tables are generated by `tools/genapi` from the pinned surface.
- Services live in a project/location scope. Creation publishes the service and
  its location ancestry into the shared resource index; IAM authorization uses
  the documented `run.services.*`, `run.revisions.*`, `run.operations.*`, and
  `run.routes.invoke` permissions, backed by pinned `roles/run.*` snapshots.
- Create and update return a `google.longrunning.Operation`. The operation
  completes from actual container readiness: a container that exits before
  readiness fails the operation with its exit status.

## Containers

- The provider owns the container lifecycle (`Runtime` seam). The Docker
  executor (`--run-docker-socket`) creates, starts, inspects, waits, stops, and
  removes one container per revision. Hosts without a socket refuse every
  launch; restricted guests develop semantics against the fake runtime.
- Workload environment: `K_SERVICE`, `K_REVISION`, `K_CONFIGURATION`, `PORT`,
  plus the service's configured plain-text environment variables. Workload
  metadata stays bound to the configured service account; the container gets no
  implicit privileged access, and backend networks grant nothing (#16/#17 scope).

## Invocation

- Services serve locally under `/_run/{service}-{project}.{location}.run.app`
  on the shared listener, mirroring the run.app hostname shape.
- Authorization before any side effect: a locally minted ID token whose
  audience matches the service URI, plus the `run.invoker` grant on the caller
  identity. Anonymous traffic is allowed only when the service policy binds
  `run.invoker` to `allUsers`.
- The authorization header never reaches the container; the proxy forwards only
  method, selected headers, and body, and streams the container's response back.
