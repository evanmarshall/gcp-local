# Cloud Tasks (local emulation)

Status: queues and HTTP-target tasks are implemented locally (issue #36, the
first #19 service slice). No cloud recording covers these methods yet, so
nothing here is a cloud-fidelity claim; the recording remains open on the
child issue.

## Surface

- REST v2beta3 routes generated by `tools/genapi`: queues
  create/get/list/delete, pause/resume/purge, tasks create/get/list/delete
  and forced `:run`, locations list.
- Task creation requires an existing queue and an http:// target; the body is
  bounded at 1 MiB.
- Dispatch: the provider owns one background worker per task with retry
  backoff (1s doubling, max 5 attempts) and forced `:run`. Tasks record
  dispatchCount and a failure detail.
- OIDC: when the task's httpRequest carries an oidcToken block, the dispatcher
  mints a local ID token bound to the configured audience for the configured
  service account - the same contract the Pub/Sub push delivery uses. The
  service-agent identity passes the mint authorization.
- Queue pause stops nothing in-flight in this slice; scheduling of future
  dispatch times is a listed gap.

## Explicit gaps

Scheduling with scheduleTime, App Engine targets, IAM policy per queue,
update of rate limits, and recorded dispatch/retry scenarios are gaps; no
"supported" claim without a recording.
