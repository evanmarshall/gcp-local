# Transport contracts

`tools/genapi` writes `api/generated/` from three inputs. The first line of each generated route file names its input.

| Input | Generated output |
| --- | --- |
| Google discovery documents pinned in `discovery/` | REST routes for Storage (plus query parameters), Memorystore for Redis, Cloud SQL, and Cloud Scheduler |
| Protobuf descriptors of Google's Go client modules, pinned in `go.mod` | Every gRPC stub, selector, and transcoding table |
| Route tables written by hand in `tools/genapi/main.go`, `tools/genapi/inference.go`, and `tools/genapi/resourcemanager.go` | REST routes for Artifact Registry, BigQuery, Bigtable admin, Cloud KMS, Cloud Logging, Cloud Run, Cloud Tasks, Compute and Network Management, Firestore, IAM, Pub/Sub, Resource Manager, Secret Manager, Spanner, Storage XML, and Vertex AI |

Hand-written REST paths are not checked against Google's API. When a hand-written route is paired with a gRPC method for transcoding, generation checks only that the route exists with the HTTP verb of the proto's `google.api.http` binding.

Storage input: the complete v1 discovery document from Google's [discovery artifact repository](https://github.com/googleapis/discovery-artifact-manager), with commit, revision, and SHA-256 in `discovery/manifest.json` and its Apache-2.0 license alongside it. It is data for generation, never a list of supported operations.

Memorystore for Redis input: the complete Redis v1 discovery document from the same repository commit, with its own source, revision, and SHA-256 in `discovery/redis-v1.manifest.json` (same Apache-2.0 license). `tools/genapi` verifies the checksum and generates routes only for an explicit method allowlist (instances create/get/list/patch/delete/getAuthString, operations get/list/cancel/delete); see [Memorystore](../docs/services/databases/memorystore.md).
Cloud Scheduler input: the complete Cloud Scheduler v1 discovery document from the same discovery artifact commit, with its source, revision, and SHA-256 in `discovery/cloudscheduler-v1.manifest.json`. `tools/genapi` verifies the checksum and generates `cloudscheduler_routes.go` for the eight job methods only, failing if one is missing. gRPC input: the `CloudScheduler` descriptors of `cloud.google.com/go/scheduler/apiv1/schedulerpb` (scheduler v1.17.0), pinned in `go.mod`; `cloudscheduler_dispatch.go` pairs each job RPC with its REST route by the same transcoding as Secret Manager. See [Cloud Scheduler](../docs/services/messaging/cloudscheduler.md).
Cloud SQL input: the complete Cloud SQL Admin v1beta4 discovery document from the same discovery artifact commit, with its source, revision, and SHA-256 in `discovery/sqladmin-v1beta4.manifest.json`. The generator emits only an allowlisted method slice and fails if a listed method is missing. v1beta4 is used because the v1 paths (`/v1/projects/{project}/instances`) collide with the Spanner admin routes on the path-only gateway; see [Cloud SQL](../docs/services/databases/cloudsql.md).

Pub/Sub input: the protoc-generated wire types and descriptors from `cloud.google.com/go/pubsub/v2/apiv1/pubsubpb`, pinned to v2.7.0 in `go.mod` and verified by `go.sum`. These are Google's published bindings for [`google/pubsub/v1/pubsub.proto`](https://github.com/googleapis/googleapis/blob/master/google/pubsub/v1/pubsub.proto). We reuse the published bindings directly instead of maintaining a second fork of their messages/compiler outputs. Their source and license are in the Go module cache; changing them requires a deliberate dependency update.

Spanner and Bigtable data-plane input: the protoc descriptors of `cloud.google.com/go/spanner/apiv1/spannerpb` (v1.95.1) and `cloud.google.com/go/bigtable/apiv2/bigtablepb` (v1.58.0) from `go.mod`. `tools/genapi` emits typed stubs for an explicit method allowlist only (`spanner_dispatch.go`, `bigtable_dispatch.go`); unary and server-streaming methods take their resource selector from the first `google.api.http` path variable, and a client-streaming method fails generation. Server-streaming stubs call `GRPCDispatch.ServerStream` with the single decoded request.

Firestore gRPC input: the published `cloud.google.com/go/firestore/apiv1/firestorepb` bindings, pinned to v1.22.0 in `go.mod`. `firestore_dispatch.go` stubs every `google.firestore.v1.Firestore` method; resource selectors merge each method's root and nested HTTP bindings (`A` and `A/*/**`) into `A/**`, where a trailing `**` matches zero or more segments. Firestore REST routes use `{path=**}` variables that span segments; the gateway unescapes each segment separately and rejects escaped slashes and dot segments.

Cloud Logging input: the `LoggingServiceV2` descriptors from `cloud.google.com/go/logging/apiv2/loggingpb`, pinned to v1.18.0 in `go.mod`. `logging_dispatch.go` forwards every RPC; resource selectors come from the HTTP annotations, and RPCs whose binding has no resource variable (entries write/list) get an empty selector, so the provider resolves and authorizes every project named in the body. `logging_routes.go` is a handwritten four-route REST allowlist using the logging v2 discovery method IDs.

Secret Manager and Cloud Tasks gRPC input: the `SecretManagerService` descriptors from `cloud.google.com/go/secretmanager/apiv1/secretmanagerpb` (v1.22.0) and the `CloudTasks` v2 descriptors from `cloud.google.com/go/cloudtasks/apiv2/cloudtaskspb` (v1.20.0), pinned in `go.mod`. `secretmanager_dispatch.go` and `cloudtasks_dispatch.go` stub every method. Their `Transcoding` tables pair an explicit method allowlist with the REST route IDs of `secretmanager_routes.go` and `cloudtasks_routes.go`, carrying each method's primary `google.api.http` verb, path, path field, and body field, plus the resource patterns of its other bindings. Generation fails if a paired route is missing or has another verb. The gateway transcodes a paired call onto its REST route, so one provider method serves both transports; Cloud Tasks v2 calls land on the v2beta3 routes. Unpaired methods and the other bindings (regional secrets) return `UNIMPLEMENTED`.
Cloud Run gRPC input: `cloud.google.com/go/run/apiv2/runpb` (run v1.23.0) and `cloud.google.com/go/longrunning/autogen/longrunningpb` (v1.2.0), pinned in `go.mod`. `run_services_dispatch.go` and `run_revisions_dispatch.go` use the same transcoding as Secret Manager: implemented methods pair with the `run.*` routes of `run_routes.go`, and `TestIamPermissions` returns `UNIMPLEMENTED`. `operations_dispatch.go` stubs the shared `google.longrunning.Operations` mixin with an unconstrained selector, like `IAMPolicy`. Its own bindings (`/v1/{name=operations/**}`) name no resource kind, so `RunServicesTranscoding` adds mixin bindings from the run v2 service config (`/v2/{name=projects/*/locations/*/operations/*}` for Get and Delete, `/v2/{name=projects/*/locations/*}/operations` for List). The gateway picks the binding whose pattern matches the operation name. `CancelOperation` and `WaitOperation` on a Cloud Run name, and any operation name no service binds, return `UNIMPLEMENTED`. Another service adds its own Operations mixin bindings the same way.

Spanner admin, Bigtable admin, and IAM service-account gRPC input: the `InstanceAdmin` and `DatabaseAdmin` descriptors of `cloud.google.com/go/spanner/admin/{instance,database}/apiv1` (spanner v1.95.1), `BigtableInstanceAdmin` and `BigtableTableAdmin` of `cloud.google.com/go/bigtable/admin/apiv2/adminpb` (bigtable v1.58.0), and `google.iam.admin.v1.IAM` of `cloud.google.com/go/iam/admin/apiv1/adminpb` (iam v1.11.0), pinned in `go.mod`. The five `*_admin_dispatch.go` files use the same transcoding against `spanner_routes.go`, `bigtable_routes.go`, and `iam_routes.go`. Spanner binds the Operations mixin's `GetOperation` to its instance and database operations routes (`/v1/{name=projects/*/instances/*/operations/*}` and the `databases/*` form, as `spanner_admin_instance.yaml` and `spanner_admin_database.yaml` rebind it). An unserved method with no HTTP binding or no resource variable (Spanner `InternalUpdateGraphOperation`) gets no selector and returns `UNIMPLEMENTED`. The IAM role RPCs bind organizations (or `roles/*` for `GetRole`) first and projects as an additional binding; `alternates` in `transcoded_admin.go` pairs each additional binding with its own REST route, the RPC's selector becomes `**`, and the gateway picks the row whose pattern matches the request's resource. `ListRoles` without a parent (predefined roles at `/v1/roles`) has no resource variable and returns `UNIMPLEMENTED`. With a `*` body and a nested path field (`service_account.name`), the body keeps the containing message. `iam_credentials_dispatch.go` pairs all four `google.iam.credentials.v1.IAMCredentials` methods (`cloud.google.com/go/iam/credentials/apiv1/credentialspb`, same module) with the IAM Credentials routes of `iam_routes.go`.

Resource Manager gRPC input: the `Folders`, `Organizations`, and `Projects` descriptors of `cloud.google.com/go/resourcemanager/apiv3/resourcemanagerpb` (resourcemanager v1.17.0), pinned in `go.mod`. `folders_dispatch.go`, `organizations_dispatch.go`, and `projects_dispatch.go` use the same transcoding against `resourcemanager_routes.go`. Collection methods whose binding has no resource variable (`ListFolders`, `CreateFolder`, `SearchProjects`) get an empty selector and are transcoded onto their route; the provider authorizes the parent the request names. `FoldersTranscoding` binds the Operations mixin's `GetOperation` to `/v3/{name=operations/*}`: the service config binds `operations/**`, and local operation IDs are one segment, so deeper names (Bigtable's `operations/projects/...`) stay with their own services. Project create, update, delete, and undelete have no route and return `UNIMPLEMENTED`.

Cloud KMS gRPC input: the `KeyManagementService` descriptors from `cloud.google.com/go/kms/apiv1/kmspb` (v1.35.0), pinned in `go.mod`, through the same generator: `cloudkms_dispatch.go` stubs every method and `CloudKMSTranscoding` pairs 21 of them with `cloudkms_routes.go`. It also pairs the `IAMPolicy` Get/Set mixin with the key ring and crypto key policy routes, one row per resource kind, with the bindings of KMS's service config (`cloudkms_v1.yaml`, GetIamPolicy on GET). A paired call whose resource the route doesn't take (`Encrypt` naming a version) returns `UNIMPLEMENTED`.

Vertex AI input: `vertexai_routes.go` is a handwritten allowlist of five publisher-model methods (`generateContent`, `streamGenerateContent`, `countTokens`, `predict`, `embedContent`) on the v1 and v1beta1 paths, named by their aiplatform v1 discovery method IDs. The aiplatform discovery document is not committed.

Generate gcp-local's separate outputs with the pinned Go toolchain:

```sh
sh scripts/go.sh run ./tools/genapi
sh scripts/go.sh run ./tools/genapi -check
```

`tools/genapi` reads the committed discovery document and checksum, plus the compiled protobuf descriptors from the pinned module. It writes one Go package per service under `api/generated/<service path>/` (`storage`, `databases/spanner`, `messaging/pubsub`, and so on, grouped like the providers), named by file as below. The shared descriptor types (`Route`, `RPC`, `Transcoding`, `GRPCDispatch`, `PubSubDispatch`) are in `api/generated/contract`, and the `IAMPolicy` and `google.longrunning.Operations` mixin stubs (`iam_dispatch.go`, `operations_dispatch.go`) in `api/generated/mixin`. Resource field selectors come from protobuf HTTP annotations; StreamingPull has an explicit initial-subscription selector because it has no HTTP binding. A new unknown streaming shape fails generation. Output is sorted/formatted deterministically; the CI runtime check fails if regeneration differs. Generation needs no GCP account or live discovery request. The first Go dependency installation requires the module proxy, after which it runs offline from the module cache.

Handwritten transport validation and dispatch live in `internal/gateway`; provider semantics will live outside the generated tree. Storage currently decodes JSON objects and escaped route variables, and leaves service field validation to providers. Pub/Sub uses the upstream protobuf codecs. Adding a route or wire type grants neither provider support nor IAM support.

The shared `google.iam.v1.IAMPolicy` gRPC bindings are also generated from the pinned `cloud.google.com/go/iam/apiv1/iampb` descriptors. Their resource selector is unconstrained in the wire definition; the registered Pub/Sub handler validates topic/subscription names and rejects other resource kinds. Get/Set policy are implemented for that slice; TestIamPermissions remains unimplemented. Cloud KMS shares the RPC by resource owner: the gateway sends a request whose resource matches a KMS mixin row's pattern to KMS, refuses an unpaired IAM method on a KMS resource (TestIamPermissions) as a KMS coverage gap, and leaves every other resource with Pub/Sub. A further service must add mixin rows the same way rather than competing registrations or an implicit administrative fallback.
